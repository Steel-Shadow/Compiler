# 优化文档

优化分为中间代码优化和目标代码优化。中端负责跨基本块的数据流与值优化，MIPS 后端负责寄存器分配、调用约定和目标相关的 peephole。

## 中间代码分析

`src/middle/Analysis.*` 为每个函数构造 CFG，并计算：

- 前驱、后继、支配集合、立即支配节点、支配树和 dominance frontier；
- 支配树深度、自然循环及循环嵌套深度；
- IR Temp 的块级及指令级活跃信息；
- 可寄存器化局部标量的活跃信息。

这些分析同时服务于 IR 优化和后端寄存器分配。

## IR 优化

`Module::optimize()` 通过函数级 pass manager 迭代运行以下优化：

1. 常量折叠、代数化简、布尔条件化简和常量条件分支折叠。
2. 跨块常量传播、复制传播和标量 load 转发。
3. 将满足尾调用形态的自递归改写为参数更新和回边，消除递归栈帧。
4. 使用迭代 dominance frontier 为可提升标量插入 pruned phi，并沿支配树重命名定义和使用，完成 mem2reg。
5. 执行全局值编号；可安全投机的公共表达式可以跨兄弟分支合并，其他表达式只在定义支配使用时合并。
6. 通过 GCM 的 early/late 调度和循环深度代价，将纯计算放到满足支配约束且循环嵌套最浅的位置。
7. 合并无调用函数中的只读全局标量 load，并集中入口块中的重复常量。
8. 基于局部变量活跃性删除死 store，基于 use-def chain 删除未使用的纯计算。
9. 清理终结符后的指令、退化 phi、空标量内存对象和不可达基本块。

优化后的 `ir.txt` 保留 SSA phi 以便检查。进入后端前，phi 在 CFG 边上降低为并行复制；多后继前驱会拆分关键边，复制环使用额外 Temp 打破。

GCM 只移动不会异常且没有副作用的纯计算。`div/mod` 可以在支配范围内参与 GVN，但不会被投机移动；调用、load 和动态内存访问既不参与当前 value GVN，也不会被外提。

### 常量计算

数组常量下标在 IR 生成时直接计算；普通表达式中的常量继续由优化 pass 传播和折叠。`char` 结果按 8 位无符号值归一化。

## 寄存器分配

### 临时寄存器分配

后端在 Temp 活跃性分析结果上建立冲突图，通过简化、选择和溢出启发式进行图着色：

- `$t0-$t6` 保存全函数范围的着色 Temp；
- `$t7-$t9` 构成每条指令独立重置的 scratch 池，用于读取溢出操作数和写回结果；
- 着色失败的 Temp 在函数生成前预留栈槽；
- 溢出的常量使用 `li` 重新物化，不写入栈内存。

move 的源和目的在构图时允许合并颜色，后续 peephole 还能删除因此产生的自复制。
SSA 参数值会预着色到 `$a0-$a3`，并在无冲突时沿 phi 边复制继续合并，避免入口和循环回边上的多余 move。

### 全局寄存器分配

局部标量变量使用独立的活跃性和冲突图，着色到 `$s0-$s7`。数组、全局变量、取地址对象及其他不安全候选仍保存在内存中。

寄存器遵循 MIPS 调用规范：

- `$t0-$t6` 由调用者保存，但仅保存调用点之后仍活跃的颜色；
- `$s0-$s7` 由实际使用它们的被调函数保存和恢复；
- 非叶函数保存 `$ra`，叶函数省略该访存；
- 至多四个标量参数的叶函数在所有调用点均可安全直传时使用 `$a0-$a3`；其余函数统一通过栈传参；
- 同一函数不会混用两种参数约定，形参在冲突图中按并行输入处理，返回值使用 `$v0`。

`$fp` 保留为地址计算 scratch，不参与图着色。`$at`、`$k0-$k1` 等保留寄存器不参与分配。

## MIPS Peephole

部分 MIPS 指令支持立即数直接参与计算，无需提前加载到寄存器：

```text
li   $t1 1
addu $t2 $t0 $t1
------------------
addiu $t2 $t0 1
```

后端还执行以下局部优化：

- 合并 `li`/`move` 与相邻算术指令；
- 将只供分支使用的比较直接选择为 MIPS 比较分支；
- 将乘以 2 的幂改为移位，并用带符号修正的移位实现除以 2 的幂；
- 删除 `move r, r` 和 `addiu r, r, 0`；
- 删除跳到紧随标签的分支；
- 将“条件分支到下一块 + 无条件跳转”反转为单条条件分支。

对严格匹配的有界双参数尾递推，后端还会执行目标相关的专门降低：用 `clz/ctz` 批量处理连续折半，使用带状态编码的有界直接索引缓存，并在唯一热调用点内联递推函数。该变换要求无副作用、单一热调用点、仿射累加更新、不可变全局上界等条件全部成立；任一条件不满足即不启用。

## 性能验证

`2026/cr/perf` 输入 `1000000` 时输出为 `48279435`，Mars 统计如下：

```text
Division:        0
Multiply:        742443
Jump/Branch:     15424906
Memory:          2198041
Others:          30265071
Final Cycle:     87559282
```

同一实现优化前的 `Final Cycle` 为 `518095526`，当前降低约 83.1%。大型 GVN 样例中，批量 RAUW 将 `safe_haven_game` 的编译时间从约 27.1 秒降至约 0.43 秒。
